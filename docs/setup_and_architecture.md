## 2. Directory Structure (Medallion Architecture)
The project follows a strict folder hierarchy to separate raw data, processed data, and source code. **Note:** Large data files are excluded from Git and tracked via DVC.

```text
madrid-mobility-intelligence/
├── .dvc/                       <-- DVC Configuration (Internal)
├── .github/                    <-- GitHub Actions (CI/CD)
├── data/
│   ├── .gitignore              <-- Auto-generated by DVC (Ignores heavy files)
│   ├── bronze.dvc              <-- DVC "Receipt" for Bronze Data
│   ├── bronze/                 <-- Raw Data (JSON/CSV/ZIP) - Tracked by DVC
│   ├── silver/                 <-- Cleaned Data (Parquet) - Tracked by DVC
│   └── gold/                   <-- Aggregated Data - Tracked by DVC
├── docs/                       <-- Project Documentation
│   ├── architecture.md         <-- Project Memory & Data Flow
│   ├── dev_log.md              <-- Development Diary (Changelog)
│   └── guides/                 <-- Technical Manuals (Git, Docker, DVC)
├── src/                        <-- Source Code
│   ├── ingestion/              <-- Scripts: Internet -> Bronze
│   ├── processing/             <-- Scripts: Bronze -> Silver -> Gold
│   └── utils/                  <-- Shared helper functions
├── .env                        <-- API Keys (IGNORED by Git)
├── .gitignore                  <-- Files to exclude from Git
├── dvc.yaml                    <-- DVC Pipeline definitions
├── docker-compose.yml          <-- Container orchestration
├── Dockerfile                  <-- Container definition
├── README.md                   <-- Main Project Presentation
└── requirements.txt            <-- Python Dependencies

```

## 3. Data Flow Strategy

* **Bronze Layer:** Raw inputs from BiciMAD (historical JSON/CSV) and EMT/AEMET (Real-time APIs). We treat this data as immutable (read-only).
* **Silver Layer:** Data is cleaned. We cast data types (e.g., string to datetime), handle null values, and remove duplicates.
* **Gold Layer:** Business-level aggregates. Features are engineered here for the ML model (e.g., "Rain intensity vs Bus delays" or "Bike usage by neighborhood").

## 4. Technology Stack & Tooling

### A. Docker (Containerization)

* **Purpose:** Ensures reproducibility. The ingestion and processing scripts run in an isolated container to avoid "it works on my machine" issues.
* **Usage:** We use `docker-compose` to spin up services (ingestion, database, notebooks).

### B. DVC (Data Version Control)

* **Purpose:** Git is designed for code (text), not massive datasets. We use DVC to track data changes without crashing the repository.
* **Workflow:**
1. **Git** tracks the *code* and the small `*.dvc` pointer files.
2. **DVC** tracks the heavy data (GBs of CSV/ZIPs).
3. Data is stored locally (or in remote cloud storage) but linked to specific Git commits.
